# E2Eテスト（同期）

本物のSupabaseの代わりにモック（`supabase-mock.cjs`）を使い、2台の端末を想定して同期の流れを確認する。
モックは `supabase/migrations` のSQLから列名を読み取り、存在しない列への書き込みをエラーとして報告する。

```bash
npm run test:e2e            # スクリーンショットはOSの一時フォルダに保存
npm run test:e2e -- ./shots # 保存先を指定
```

確認している内容：ログイン（誤ったパスワード）、顧客コードの採番、写真のアップロードと端末の大きい画像の削除、追加写真、
別端末への反映、圏外時の未送信と仮顧客、送信失敗と再送、アカウント停止、サーバーに届かない状態での再起動。
最後の行の `column/route errors` と `page errors` が空であること。

## PC管理画面のテスト

```bash
npm run test:e2e:admin -- ./shots
```

スマホで記録（GPS付きの取り込み・撮影・追加写真・圏外での仮顧客）を作ったあと、PCで `#admin` を開き、顧客・台帳一覧、記録の表示、地図、PDFレポート、ZIPダウンロード、仮顧客の紐づけ、削除と復元を確認する。
`fixtures/` の写真はテスト用に生成した架空の画像（Exifの日時・位置も架空）。

## ステップ4のテスト（項目単位マージ・衝突・重複・統合）

```bash
npm run test:e2e:step4 -- ./shots
```

2台のスマホで同じ記録・台帳を圏外で同時に編集し、同じ項目は後から送った内容を採用・違う項目は両方反映・衝突の履歴と通知を確認する。
通知から作業記録を開き、変更履歴から「変更前の内容に戻す」。似た名前の台帳の重複通知、PCでの比較・統合（統合を知らない端末からの記録が統合先に入ること、
開いていた台帳の切り替え）、統合の取り消し、「重複ではない」、操作ログ、PCの作業記録の変更履歴を確認する。各項目に OK / NG を表示し、最後に `ALL PASSED` が出ること。

モックはサーバーのトリガー（`merge_update` など）と同じ動きを JavaScript で再現している。SQL自体は、ローカルの PostgreSQL に認証まわりの簡易版を用意して流し、
衝突・統合・取り消し・権限を確認した（手順は省略。SQLを変えたときはモックも合わせて直すこと）。
