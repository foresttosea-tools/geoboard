# GeoBoard 要件定義書

- バージョン：0.1（ドラフト）
- 作成日：2026-11-16
- 作成者：芦田 佑介（株式会社フォレストシー）
- 対象読者：開発者本人、および開発を支援するAI（Claude Code）

---

## 1. 概要

GeoBoardは、現場での設置工事を記録するための社内向けPWA。工事黒板を重ねた写真を撮影し、顧客・台帳単位で整理して保存する。携帯の圏外になる山間部などでの利用を前提とし、オフラインで撮影・登録したデータは、通信可能になった時点でサーバーへ自動アップロードする。

### 1.1 目的

- 現場写真と黒板情報をセットで、漏れなく・迷わず記録する
- 圏外の現場でも作業を止めない
- 事務所側（PC）で写真の確認、地図での位置確認、提出用PDFレポートの出力を行えるようにする

### 1.2 利用範囲

- 社内（株式会社フォレストシー）のメンバー。将来的に協力会社が使う可能性あり
- 全ユーザーが同じデータを共有して編集する（個人ごとにデータは分かれない）

## 2. 基本方針

| 項目 | 決定内容 |
|---|---|
| アプリ形態 | PWA（ホーム画面に追加して使用） |
| 対象端末 | スマホのみ（iOS / Android）。タブレット最適化はしない |
| PC管理画面 | 同じPWAをPCブラウザで開き、PC向けレイアウトで表示 |

| サーバー（本番） | 未定（自前サーバー / VPS / SharePoint を検討中）。接続先アダプターで差し替え可能にする |
| アプリの公開先 | GitHub Pages（公開リポジトリ、個人アカウント） |
| 開発体制 | 芦田がClaude Codeを使って開発 |

## 3. 用語

| 用語 | 意味 |
|---|---|
| 顧客 | 工事の発注元。顧客コードはサーバーが自動採番する |
| 仮顧客 | 圏外で作成した未確定の顧客。オンライン復帰後に管理者が確定させる |
| 台帳 | ひとまとまりの工期・工事。顧客の配下に作成する |
| 作業記録 | 台帳の中に保存される1回分の撮影データ（写真＋黒板＋位置情報など） |
| 黒板 | 写真に重ねる工事黒板。7つの枠で構成される |
| 作成した黒板 | 名前を付けて保存した黒板の内容。全ユーザーで共有する |
| 撮影モード | 黒板あり / 黒板なし / 両方 の3種類 |
| 引継ぎ事項 | 次回への引継ぎ事項。黒板には載せず作業記録に保存し、レポートに載せるかを記録ごとに選ぶ |
| 原本 | 黒板を合成していない写真 |
| 合成画像 | 原本に黒板を焼き込んだ写真 |

## 4. ユーザーと権限

### 4.1 アカウント

- 個人ごとにアカウントを発行する（メールアドレス＋パスワード）
- 権限は「管理者」「一般」の2種類
- 一度ログインしたら、ログアウトするまでオンライン・オフラインを問わず使える
- 管理者がアカウントを停止すると、その端末は次にオンラインになった時点で強制ログアウトされる
  - 強制ログアウトの前に未送信データがあれば、アップロードを済ませてからログアウトする

### 4.2 権限表

| 操作 | 管理者 | 一般 |
|---|---|---|
| 顧客の作成・編集 | ○ | ○ |
| 顧客の削除 | ○ | × |
| 仮顧客の作成（オフライン時のみ） | ○ | ○ |
| 仮顧客の確定（既存顧客へ紐づけ / 正式登録） | ○ | × |
| 台帳の作成・編集 | ○ | ○ |
| 台帳の削除 | ○ | × |
| 台帳の統合・統合の取り消し | ○ | × |
| 撮影・作業記録の追加・編集 | ○ | ○ |
| 作業記録の削除 | ○ | 自分が撮影したもののみ |
| 作成した黒板の保存・呼び出し | ○ | ○ |
| 作成した黒板の削除 | ○ | 自分が作成したもののみ |
| ユーザー管理（発行・停止・権限変更） | ○ | × |
| サーバー接続先の設定 | ○ | × |
| 会社情報（レポート用）の設定 | ○ | × |

### 4.3 共通ルール

- 削除はすべて論理削除とし、管理者がもとに戻せる
- 作成・編集・統合・削除の操作ログ（誰が、いつ、何を）を残す
- 施工者名の初期値には、ログイン中のユーザーの表示名を入れる（編集可）

## 5. データ構造

### 5.1 階層

```
顧客（customers）
└─ 台帳（ledgers）
   └─ 作業記録（records）
```

### 5.2 ID方針

- すべてのレコードのIDは、端末側でUUID（v4）を生成する。オフラインで作成しても、サーバー同期時にIDが衝突しない
- 顧客コードのみ、サーバー側で連番を採番する（例：`C-0001`）

### 5.4 ストレージ構成

```
photos/
└─ {customer_id}/
   └─ {ledger_id}/
      ├─ {record_id}_composite_{版}.jpg
      ├─ {record_id}_original_{版}.jpg
      ├─ {record_id}_thumb_{版}.jpg
      └─ {record_id}_extra_{extra_id}_{版}.jpg   … 追加写真

- {版} は送信のたびに変わる印。黒板の修正などで写真を作り直したとき、同じファイル名に上書きすると端末やサーバーの一時保存から古い写真が表示されるため、毎回別の名前で保存する
- 作り直す前の古い画像はサーバーに残る（容量の整理は今後の課題）
```

- PC管理画面からZIPでダウンロードする際は、`{顧客名}_{工事名称}/{撮影日}_{連番}.jpg` に名前を変換して格納する

## 6. 機能要件（スマホアプリ）

### 6.1 顧客

- 顧客はオンライン時のみ作成できる。顧客コードはサーバーが自動採番する
- 顧客一覧はオンライン時に端末へ同期・キャッシュし、オフラインでも選択できる
- オフライン時のみ、顧客選択画面に「仮顧客を作成」ボタンを表示する
  - 仮顧客は顧客名のみ入力。一覧では「仮」ラベルを表示する
  - オンライン復帰後、管理者に通知する。管理者は「既存顧客に紐づける」か「正式登録（コード採番）」を選ぶ
  - 紐づけ先の顧客に類似の台帳があれば、重複候補チェック（6.2）を実行する

> **ステップ2時点の暫定動作**：サーバーがまだないため、顧客は端末内でいつでも作成でき、顧客コードは未採番（null）のまま。オンライン限定の作成・コード採番・仮顧客はステップ3で対応する。顧客・台帳の削除は権限（管理者のみ）と合わせてステップ3以降で対応する。
> 同じ名前の顧客を作ろうとすると、重複の可能性を警告する。

### 6.2 台帳

- 登録項目：工事名称、工期（開始日・終了日）、工事責任者、備考
- オフラインでも作成できる
- 完了・進行中の区別はしない
- アプリを開き直すと、前回開いていた台帳の作業記録一覧から再開する（台帳から戻ると解除）
- 一覧の並び順：最近更新した順（初期値）/ 工期の開始日順 / 工事名称順
- 検索：顧客名、工事名称、工事責任者

#### 重複候補の検出と統合

- 同じ顧客の配下で、次のいずれかに当てはまる台帳を重複候補とする
  - 工事名称が類似（全角半角・空白・表記ゆれを正規化して比較）
  - 工期が重なっている
- 同期のタイミングで検出し、管理者に通知とバッジで知らせる
- 統合画面では2つの台帳を左右に並べ、項目ごとに残す値を選ぶ
- 作業記録は両方の台帳の分を合算し、撮影日時順に並べる
- 統合された側の台帳は削除せず `merged_into` を設定して非表示にする。統合の取り消しが可能
- 「重複ではない」を選んだペアは、以後候補に出さない

### 6.3 作業記録の一覧

- リスト表示とグリッド表示を右上のボタンで切り替える。最後に使った表示を記憶する
  - リスト表示：サムネイル、撮影日、作業場所、作業内容、施工者
  - グリッド表示：サムネイル3列、右下に撮影日
- 並び順：撮影日時の新しい順（初期値）/ 古い順
- マーク表示：「未送信」「送信失敗」「日付要確認」「取込画像」「位置なし」
- 画面上部：未送信件数のバッジ、送信進捗（例：3/5件）、「再送」ボタン
- 画面下部：撮影ボタン（固定）、画像取り込みボタン

### 6.4 黒板

#### レイアウト（固定）

| No | 初期の項目名 | 表示ルール |
|---|---|---|
| 1 | 顧客名 | 1行に収まるよう文字サイズを自動縮小 |
| 2 | 作業場所 | 1行に収まるよう文字サイズを自動縮小 |
| 3 | 作業内容 | 1行に収まるよう文字サイズを自動縮小 |
| 4 | 機材（通信機器 / 電源） | 1行に収まるよう文字サイズを自動縮小 |
| 5 | 撮影日 | 1行に収まるよう文字サイズを自動縮小。初期値は当日。カレンダーから選択可 |
| 6 | 備考 | 3行分の高さ。枠内で折り返し、収まらない場合は文字サイズを自動縮小 |
| 7 | 施工者名 | 1行に収まるよう文字サイズを自動縮小。初期値はログインユーザーの表示名 |

- 7つの枠の配置は固定。項目名・内容ともにタップで編集できる
- 黒板を開いたときは、その台帳で最後に使った黒板の内容（`ledgers.last_blackboard`）を表示する。撮影日だけは当日の日付にする
- 顧客名の初期値には、台帳の顧客名を入れる

#### デザイン

- 濃い緑の背景、白い文字、白い罫線
- 木枠はなし（外周は白い罫線のみ）
- 会社名・ロゴは表示しない（将来の追加に備えて設定項目の余地だけ残す）

#### 作成した黒板

- 名前を付けて保存し、全ユーザーで共有する
- 一覧は「最近使った順」「名前順」で並び替え可能。名前で検索できる
- 削除できるのは作成者と管理者のみ
- 呼び出すと項目名と内容を一括で反映する。撮影日は当日の日付にする
- オフラインでも、最後に同期した時点の一覧から呼び出せる

#### 次回への引継ぎ事項

- 黒板には載せず、作業記録の項目として保存する
- 黒板編集画面（撮影前）で入力でき、作業記録の詳細画面（保存後）でも修正できる
- 「レポートに載せる」を作業記録ごとに選べる（初期値：載せない）
- 前回の内容は引き継がない（撮影のたびに空欄から始まる）

#### 黒板オフ

- 黒板オフボタンで、黒板なしでの撮影に切り替えられる

### 6.5 撮影

#### 撮影モード

| モード | 保存するもの | 保存後の黒板修正 |
|---|---|---|
| 黒板あり | 合成画像のみ | 不可（メモ欄で補足・訂正） |
| 黒板なし | 原本のみ | 黒板がないため記録情報のみ編集可 |
| 両方 | 合成画像＋原本 | 可（再合成してサーバー上の画像を差し替え） |

#### カメラ画面

- カメラ映像の上に黒板を重ねて表示する
- 黒板はドラッグで移動、ピンチでサイズ変更できる。操作は黒板の上でのみ受け付ける
- 縦横どちらの向きでも撮影可能。端末の向きに合わせてアイコンを回転させる
- 黒板の位置・サイズは縦向き用と横向き用で別々に記憶する
- 撮影補助機能
  - ズーム：ピンチ操作。倍率を表示（iOSはデジタルズーム）
  - グリッド線：3×3。オン・オフを記憶
  - 水平器：画面中央に傾きを表示し、水平で色が変わる
- 対応しない機能：フラッシュ、タップでのピント合わせ

#### 画像の仕様

- 長辺3000〜4000px前後、JPEG（画質85〜90%）
- 1枚あたり約2〜4MB

#### 位置情報

- 撮影時の緯度・経度と測位精度を記録する
- 測位できない・時間がかかる場合でも撮影はブロックしない。位置情報なしで保存し「位置なし」マークを付ける
- 初回に位置情報の利用許可を求める

### 6.6 端末内の画像の取り込み

- 端末の写真から1枚または複数枚を選択できる
- 選んだ写真は**1つの作業記録**になる。1枚を**メイン写真**にして黒板を付け、残りは黒板なしの**追加写真**として登録する
  - メイン写真の初期値は撮影日時がいちばん古い写真。取り込み画面の下に並ぶサムネイルから選び直せる
  - 保存方法（黒板あり / なし / 両方）はメイン写真に適用する
- 撮影日と位置情報は、メイン写真のExifから自動で入れる（撮影日は編集可）
- Exif日時がない場合は当日の日付を仮に入れて「日付要確認」を付ける。撮影日を変えるか「この日付でOK」を押すと外れる。保存後は詳細画面で確定できる
- Exifに日時がない写真の撮影日時は、選んだ日付の正午として扱う（一覧の並び順を黒板の撮影日と合わせるため）
- 黒板の位置・サイズは、縦長用・横長用の配置を記憶して使う（撮影画面と共通）
- 作業記録には「取込画像」マークを付ける

### 6.7 作業記録の詳細・編集

- 写真の拡大表示（黒板あり / なしの切り替えは、両方保存している場合のみ）
- 黒板の内容、撮影日、メモ、引継ぎ事項（レポート掲載の有無を含む）を編集できる。黒板の修正可否は6.5の表に従う
- 再合成できない記録で黒板を編集しようとした場合、「両方で保存していないため写真は修正できません」と表示する
- 位置情報は、緯度・経度を長押しするとコピーでき、「地図」ボタンでGoogleマップを開ける
- 「日付要確認」の記録は、詳細画面で撮影日を確定できる。「両方」で保存した記録は黒板の撮影日も直して写真を作り直す。それ以外は記録の撮影日時だけを直す（写真の黒板は直せないため）
- 変更履歴を表示し、以前の内容に戻せる
- **追加写真**：メイン写真（撮影モードを選んで撮った写真）とは別に、黒板なしの写真を何枚でも追加できる
  - 「撮影して追加」はスマホ標準のカメラ、「写真から追加」は端末の写真から複数枚選択
  - 閲覧用（全画面表示・スワイプで切り替え・削除）。PDFレポートには載せない。サーバー同期の対象にはする
- 画面下部の「前へ」「次へ」ボタンで、一覧の並び順どおりに前後の作業記録へ移動できる（文字の選択と干渉するため、スワイプでの移動はしない）
- 引継ぎ事項などを編集したまま移動・戻ろうとした場合は、「保存して移動 / 保存せずに移動 / キャンセル」を選ぶ確認を出す

### 6.8 設定画面

- サーバー接続先（接続先の種類、URL、接続キー）※管理者のみ
- 未送信警告までの日数（初期値：3日）
- ログイン中のユーザー情報、ログアウト
- アプリのバージョン、ストレージ使用量

## 7. オフラインと同期

### 7.1 端末内の保存

- IndexedDBに、顧客・台帳・作業記録・作成した黒板・未送信の画像を保存する
- 起動時に `navigator.storage.persist()` で永続化を要求する
- 利用はホーム画面に追加したPWAからを前提とする（Safariの7日ルールの対象外にするため）。ブラウザのタブで開いた場合は、ホーム画面への追加を促す
- 送信済みの作業記録は、サムネイルのみ端末に残し、元画像は必要なときにサーバーから読み込む

### 7.2 アップロード

- 撮影直後、アプリを開いたとき、オンラインに復帰したときに自動送信する
- 送信は1件ずつ。失敗時は間隔を空けて自動リトライ（最大3回）
- それでも失敗したものは「送信失敗」マークを付け、手動の「再送」ボタンで送り直せる
- サーバーに画像を保存したあと、サーバー上のサイズが送信したものと一致することを確認してから、端末内の大きい画像（合成画像・原本・追加写真）を削除する。サムネイルは残す
- 未送信のまま設定日数を超えたら、起動時に警告を出す
- iOSのPWAはバックグラウンド送信に対応しないため、アプリを開いている間に送信する

### 7.3 同時編集の衝突

- 写真の追加は衝突しない（追加のみ）
- 台帳・作業記録の項目は、項目単位でマージする
  - 異なる項目の編集：両方を反映
  - 同じ項目の編集：後から同期した内容を採用
- 上書きされた内容は `change_logs` に `conflict_overwrite` として残し、画面から復元できる
- 衝突が起きたら、上書きされた側のユーザーと管理者にアプリ内通知を送る

### 7.4 同期の順序

1. 顧客（仮顧客を含む）
2. 台帳
3. 作業記録のデータ
4. 画像
5. 作成した黒板
6. サーバーからの差分取得（顧客一覧、台帳、作業記録、作成した黒板、通知）
7. 重複候補の検出

## 8. PC管理画面

### 8.1 機能一覧

- 顧客 → 台帳 → 作業記録の階層で一覧表示
- 検索・絞り込み：顧客名、工事名称、工期、撮影日、施工者、キーワード
- 写真のプレビューと拡大表示（黒板あり / なしの切り替え）
- 写真のダウンロード（1枚ずつ、または台帳単位でZIP）
- 地図表示：台帳内の撮影地点をピンで表示。ピンをクリックで写真と黒板の内容を表示
  - 地図は国土地理院タイル（標準地図・航空写真を切り替え）、Leafletで表示
- PDFレポート出力（8.2）
- 台帳の重複候補の確認と統合（管理者）
- 仮顧客の処理（管理者）
- ユーザー管理（管理者）
- 操作ログ・変更履歴の閲覧（管理者）
- 会社情報の設定（施工会社名、ロゴ）（管理者）

### 8.2 PDFレポート

- 出力単位：台帳ごと（撮影日の範囲で絞り込み可）
- 用紙：A4縦
- **表紙**：顧客名、工事名称、工期、工事責任者、施工会社（株式会社フォレストシー）、出力日
- **本文**：1ページに写真3枚を縦に並べ、各写真の右側に入力内容を表示
  - 入力内容：作業場所、作業内容、機材、撮影日、備考、施工者名、緯度・経度、メモ
  - 次回への引継ぎ事項は「レポートに載せる」を選んだ記録のみ記載する
  - 写真の下に撮影日時と施工者名を小さく記載
  - 縦長の写真は枠内に収めて左右に余白を入れる
- ヘッダーに工事名称、フッターにページ番号
- 黒板あり / なしのどちらを載せるか切り替え可能。載せない写真はチェックで除外できる
- 施工会社名・ロゴは設定から変更可能
- 日本語フォントを埋め込んでブラウザ内で生成する

| 項目 | 状況 |

| 本番のサーバー | テストはSupabase（クラウド無料プラン）。本番は次から選ぶ：Supabase有料プラン / Supabase無料＋Cloudflare R2 / VPS＋PocketBase / 会社サーバーでSupabaseをセルフホスト / SharePoint。詳細は下記 |

### 本番サーバー検討メモ

- 費用の大半は写真の保存容量。1現場約30MB（「両方」保存時）、月20現場で年間約7GBの見込み
- Supabaseのセルフホスト版はオープンソースでライセンス料は不要。クラウド版からはデータベースと写真をそのまま移せる
- SharePointを使う場合、ブラウザアプリ（PWA）のMicrosoftログインは24時間で切れる（延長不可）。圏外での撮影・保存はログイン不要に作れるが、送信時に毎日サインインし直しになる可能性がある。避けるには、GeoBoard独自のログインにして、間のサーバー（Azure Functionsなど）からSharePointへ読み書きする構成にする
- どの方式でも、端末側はオフライン優先のため、サーバー停止中も撮影・保存は継続できる
| 黒板への会社名・ロゴの表示 | いったん表示しない |
| 設定画面の細かい項目 | 6.8を初期案とし、開発中に追加検討 |
| 協力会社の利用 | 可能性あり。利用する場合はアカウント発行ルールを決める |
